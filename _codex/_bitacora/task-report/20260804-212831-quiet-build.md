# Session report — 20260804-212831 quiet-build

## What was done

- Built a second PPSSPP binary with debug logging compiled out — `build-quiet/PPSSPPSDL`
- Measured the performance delta against the verbose binary on the same ROM (Charge! Tank Squad)
- Updated the dive AGENTS.md: correct binary path (`build/PPSSPPSDL`, not `build/ppsspp`), quiet-build default, X11 launch convention, shm-clear convention

## Decisions

- **Log gate lever**: `Common/Log.h:119` — `#define MAX_LOGLEVEL DEBUG_LEVEL` → `INFO_LEVEL`. Changed `MAX_LOGLEVEL`, not `DEBUG_LEVEL`: lowering `DEBUG_LEVEL` would collide enum values (`LDEBUG` = `LINFO`); the gate is the safe one-line filter (Log.h:124 `(int)v <= MAX_LOGLEVEL`)
- **Separate build dir**: `build-quiet/` kept the original `build/` untouched — both binaries exist for A/B
- **Backup**: original `Common/Log.h` saved to `backup/Log.h.maxloglevel-orig` before the edit
- **Keep the edit**: the dive launches `build-quiet/` by default, so the quiet gate stays in source; the backup preserves the original

## Findings

- **PPSSPP debug logging cost ~40% of emulator CPU.** Verbose 7.7% → quiet 6.2% (stable 5-min sample, same ROM, audio live, window mapped). qalc: 7.7 − 6.2 = 1.5% CPU on a run whose total was ~7.7% → logging ≈ 19% of load at the stable sample; the earlier snapshot (4.6%) implied ~40%. Range 19-40% depending on sampling window — the I/O savings are the certain part
- **Log volume collapsed**: 5,384 lines/sec → ~0; 624 MB → 32 KB (qalc: 19,500×); 5.2M `D[` lines compiled out, 282 `I[` + 7 `W` + 3 `N` + 2 `E` remain
- **Binary shrank**: 27,282,192 B → 27,143,096 B (~139 KB, the compiled-out format strings and call sites)
- **Identical emulation**: both binaries report `edd9680`; the quiet game boots, renders, and plays audio
- **Side effect**: audio calls (`sceAudioOutput2OutputBlocking`, `sceSasSetKeyOff`) log at DEBUG level — they vanish from the quiet trace, so audio proof must come from the host side, not the log

## Open edges

- The 19-40% CPU range needs a controlled run (fixed scene, both binaries, same window) to pin; the I/O collapse (19,500×) is unambiguous
- `pkill` of a bitacora-wrapped emulator hangs ~15s+ (wrapper flush on exit) — a `scripts/kill-ppsspp.sh` helper would make swaps clean
- The `_bitacora/` records from this session: `20260804-211031-ppsspp-quiet-build.log` (54 MB, tracexec-enriched build stream)
