## Decisions

```
1. New precepts as six individual template files, one rule per file — matches the
   precept naming convention (action-domain, atomic) and the dive's realized layout
2. Precept templates named precept-{action}-template.md — disambiguates from the generic
   precept-template.md while keeping the *-template.md suffix
3. concept/ inserted into the general chain between study/ and fixture/ — the dive's
   ring diagram already placed it in ring 2 (backup → study → concept); the flat chain
   now matches the rings

   study-template only references the anchor

   SOV, actor-first, declarative register, affirmative framing; imperative practice
   steps and negation phrasing converted
```

## Errors found

## Findings

```
1. The mgba-repo dive is the realized instance of the codex template set — its
   AGENTS.md, precepts, invariants, and guideline fill in every generic template with
   concrete form. Templates improve by reading the dive, not the other way around
2. Ring structure (0-3 ordinal) formalizes what the flat chain implied — foundation →
   record+governance → safety+understanding → proof+structure+steps. The flat chain
   omitted concept/ even though the dive's ring diagram included it — a latent
   inconsistency now resolved in the template source
3. The dive's 7 precepts split into generic forms (precept-template.md already covered
   the shape) and doctrine (qalc, metrics, fixtures, atomic docs, rg, shared browser) —
   the doctrine becomes reusable only as explicit templates
4. Communication-rule compliance must gate template authoring — templates are
   instruction artifacts; imperative/negation phrasing violates the positive-ratio
   doctrine at the layer where it matters most
5. Propagation via copy-templates.sh is the sync point — verification after copy
   (15/15 SYNC) confirms the dive's template/ mirrors _templates/
```
