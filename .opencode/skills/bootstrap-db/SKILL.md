**Procedure**

**1. Pre-flight** — confirm project warrant per `REF.META.PROJECT.STRUCTURE`:
- Check `AGENTS.md` and root directories for existing projects. New project warrants when: needs 3+ related tables, dedicated CRUD tools, or domain-specific business logic
- Check DB criterion per `REF.SCHEMA.DATABASE.OWNERSHIP`: domain data survives across tool invocations, needs structured querying, and is domain-specific
- Determine mutation pattern per entity per `REF.LIB.MUTATION.STRATEGY`: event/time-series → append (`INTEGER PRIMARY KEY AUTOINCREMENT`), source/registry → upsert (`TEXT PRIMARY KEY`, `ON CONFLICT DO UPDATE`)
- Create mandatory `.opencode/` structure: `tools/`, `lib/`, `AGENTS.md`, `opencode.json`

**2. Define domain** — delegate to `/db-domain` (`.opencode/commands/define-domain.md`)
- Pass `$ARGUMENTS` as the project directory name
- Output: `.opencode/manifests/domain.md`

**3. Define groupings (optional)** — delegate to `/db-groupings` (`.opencode/commands/define-groupings.md`)
- Skip when entities are flat (same directory, same table for all)
- Output: `.opencode/manifests/groupings.md`

**4. Identify entities** — delegate to `/db-entities` (`.opencode/commands/identify-entities.md`)
- Output: `.opencode/manifests/entities.md`

**5. Define properties** — delegate to `/db-properties` (`.opencode/commands/define-properties.md`)
- Output: `.opencode/schemas/db.sql`, `.opencode/manifests/properties.md`
- Optional: `.opencode/schemas/seed.sql` per `PROT.SCHEMA.FORMAT`

**6. Scaffold tools** — delegate to `/db-tools` (`.opencode/commands/scaffold-tools.md`)
- Generates: `lib/paths.ts`, `lib/errors.ts`, `lib/db.ts`, read/write/audit CLI tools, `AGENTS.md`, `package.json`, `.gitignore`, `manifests/logic.md`

**7. Verify** — run `bun run .opencode/tools/read-{entities}.ts` to confirm tools execute. Run root `verify-deps` to confirm symlink resolves

**Gotchas**

- Check existing projects first — `AGENTS.md` and root-level directories with their own `AGENTS.md`. Place the new domain in an existing project when overlap exists
- `/db-groupings` is optional — skip if entities are flat
- Run commands in order — each depends on the previous manifest
- Use `question` tool for each interactive step — the commands instruct gathering info from the user
- Schema evolves additively — `ALTER TABLE ADD COLUMN`. DROP excluded
- All five commands use `subtask: true` — runs in subagent, keeps primary context clean
- WAL sidecar files (`-wal`, `-shm`) are transient — `.gitignore` is generated by `/db-tools`

**Rules**

- Mandatory structure (AGENTS.md, opencode.json, lib/, tools/) created before entity definition — per `REF.META.PROJECT.STRUCTURE`
- DB criterion checked before creating `.db` — per `REF.SCHEMA.DATABASE.OWNERSHIP`
- Mutation pattern determines PK type and sync direction — decide before scaffolding per `REF.LIB.MUTATION.STRATEGY`
- Run commands in order — each depends on the previous manifest
- Step 7 is mandatory — verify generated tools before declaring done
