# mcp-rom-acquire — snes9x acquisition orchestrator MCP server

Timestamp: 2026-07-31 21:50

## What was done

Built an MCP server wrapping the snes9x dive's atomic ROM acquisition scripts, with step-status tracking. Lives in the dive's hidden `.opencode/`:

`_codex/snes9x-repo/.opencode/mcp/mcp-rom-acquire/`

### Structure

| File | Role |
|------|------|
| `package.json` | deps `@modelcontextprotocol/sdk` ^1.16.0, `zod` ^4.0.0 |
| `tsconfig.json` | ESNext, strict, noEmit |
| `node_modules` | symlink → root `.opencode/node_modules` (SDK 1.29.0, zod 4.1.8) |

## Decisions

- **Location** — user directive: code lives in the snes9x dive's hidden `.opencode/`, not the root `.opencode/`. Root scaffold moved and removed.
- **Wrapper over custom tools** — user chose wrapper-of-all-scripts (one tool per script) over a 7-custom-tool design; server adds only step-status tracking on top.
- **Purity split** — query (io) owns script exec + state I/O; types/format (pure) own interfaces and formatting; `import type` across boundary.
- **Symlink deps** — mirrors active mcp-findings convention (root node_modules), no per-server install.
