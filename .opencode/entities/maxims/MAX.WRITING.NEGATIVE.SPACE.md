**Negative Space** — every markdown entity file uses declarative text, lists, and code blocks. Markdown tables are prohibited. Negative space is appreciated.

## Expression

- **Declarative prose** over markdown tables — field definitions, gotchas, comparisons, and schema documentation use sentences and lists, not grid layouts
- **No markdown tables** in any entity file — applies to all entity types across all groups: maxims, specifications, protocols, patterns, terms, references, illustrations, persons, identities
- **Negative space** — short sentences, single-line items, generous vertical spacing. Tables compress information into dense grids. Negative space lets each fact breathe

## Rules

- Markdown tables are prohibited in all entity `.md` files across all groups
- Use declarative sentences with `- ` bullet lists for field definitions
- Use subheadings and prose paragraphs for comparisons
- Use code blocks for structured data where needed
- Prefer one line per item over one row per concept

## Applicability

All entity `.md` files across all groups and rings.
