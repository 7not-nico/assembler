## Context

A new project `study-sessions/category-theory/` needs a `.opencode/` directory. The tiered structure determines what goes in based on the project's feature needs.

## Tier system

| Tier | Items | Condition |
|------|-------|-----------|
| Mandatory | `tools/`, `lib/`, `AGENTS.md`, `opencode.json` | Always |
| Required | `schemas/`, `package.json`, `bun.lock`, `.db` | Conditional |
| Optional | `plugins/`, `inspirations/`, `notes/` | Per domain |

## Walkthrough

### Step 1: Mandatory items (always)

```
study-sessions/category-theory/.opencode/
  tools/           ← tool files (shebang CLI or MCP servers)
  lib/             ← shared logic (imported by tools)
  AGENTS.md        ← project instructions
  opencode.json    ← project config
```

These four exist in every subproject regardless of domain. Missing any one is a structural violation.

### Step 2: Required items (conditional)

The project needs a SQLite database to store definitions and proofs. This triggers the schema condition:

```
study-sessions/category-theory/
  .opencode/
    tools/
    lib/
    schemas/       ← required: .db exists
      seeds/       ← required: seed data needed
        01-definitions.sql
        02-proofs.sql
    AGENTS.md
    opencode.json
  category-theory.db  ← required: paired with schemas/
```

If the project also imports from an npm package (e.g., `zod` for proof validation):

```
study-sessions/category-theory/.opencode/
  package.json     ← required: npm imports exist
  bun.lock         ← required: generated by bun install
  node_modules/    ← required: installed dependencies
```

### Step 3: Optional items (per domain)

The project benefits from lifecycle hooks (auto-validate proofs on file edit):

```
study-sessions/category-theory/.opencode/
  plugins/         ← optional: lifecycle hooks needed
    auto-validate.ts
```

`inspirations/` and `notes/` added only if the domain needs reference materials or scratch space.

## Decision flow

```
New subproject
│
├─ Always add: tools/, lib/, AGENTS.md, opencode.json
│
├─ Has a .db file?
│   ├─ Yes → add schemas/ (with seeds/ if seed data needed)
│   └─ No  → schemas/ excluded
│
├─ Has npm imports?
│   ├─ Yes → add package.json, bun.lock, node_modules/
│   └─ No  → package.json excluded
│
└─ Needs lifecycle hooks?
    ├─ Yes → add plugins/
    └─ No  → plugins/ excluded
```

## Key insight

The tiered structure prevents both over-engineering and under-structuring. Mandatory items ensure minimum navigability for any agent entering the project. Required items emerge from feature needs — a project with no DB omits schemas/. Optional items serve domain-specific needs without structural review.
